## Synthesis & Architectural Assessment

1. **Storage Capacity (Risk R1 Retired for DB)**:
   - Both question definitions (`surveyJson`, `answerKey`) and student responses (`responses`) are stored in PostgreSQL `JSONB` columns (`Quiz.surveyJson`, `Quiz.answerKey`, `QuizAttempt.responses`).
   - Neither column is constrained by SQL `VARCHAR` limits. Payload limits are enforced at the application layer (Express JSON parser 512 KB, `quizConfig.js` 256 KB).

2. **Student Exposure of Reference Answers (AC-6 Security Boundary)**:
   - In `getQuizResult` (`src/controllers/quizController.js:347-348, 370`), when `attempt.status === STATUS.GRADED && passed`, `modelAnswer: keyEntry.modelAnswer` is exposed to students.
   - This exact leak has been pinpointed and will be removed in Phase 1.4 to enforce Invariant AC-6.

3. **AI Essay Grader Architecture**:
   - `src/services/aiGrader/prompts.js` (`PROMPT_VERSION = 'v1'`) and `schemas.js` (`RawVerdictSchema`) define the current grading contract.
   - `criteriaBreakdown` is confirmed absent across DB and schemas.
   - Fallback routing to human teacher inbox occurs whenever `confidence < 0.8`.
   - Evaluation runner is `scripts/ai-eval.js` with 4 test scenarios.

4. **Quiz Interface & Rendering**:
   - `QuizRunner.tsx` uses custom React components per question type rather than SurveyJS UI components. For essay questions, `comment` renders a `<textarea>`.
   - Results in `QuizReviewList.tsx` and grading in `GradingForm.tsx` currently render plain strings inside `whitespace-pre-wrap` containers.
   - Replacing these containers with `<RichView>` provides KaTeX math and chemistry rendering without disturbing quiz lifecycle, timer, or 25-second autosave logic.

5. **No i18n Dictionary System**:
   - Both backend and frontend lack multi-lingual translation dictionaries (`locales/`, `messages/`).
   - The frontend hardcodes Arabic UI text with `<html lang="ar" dir="rtl">`.
   - The backend uses hardcoded English error strings. Error handling in Phase 1+ must use structured error codes (`RICH_*`) so the frontend can display localized Arabic alerts.
