# Implementation Plan: Admin Dashboard (Admin Console)

Status: **COMPLETE (P0–P3 all shipped + browser-verified; P4 polish deferred as out-of-scope)** — Repos: backend `H:\e-learning-platform`, frontend `L:\E-LRN-FRONTEND\a-e-lrn-frontend`

## Overview

Build a unified admin console for the e-learning platform. Today admin functionality is scattered (3 quiz pages + ad-hoc endpoints, no shell, no overview, no tables). This plan delivers a navigable console with an Overview/KPI page and management sections (Students, Courses, Videos, Quizzes, Grading inbox, Enrollments), reusing existing backend controllers and endpoints wherever possible. Architecture leaves thin seams (sidebar nav config, single `/admin` API namespace, reusable `DataTable`) so future features drop in without rework.

## Architecture Decisions

1. **Scope: full console** (shell + all management sections), not just an overview page. The shell IS the integration surface for future features.
2. **BE: dedicated `/admin` namespace** mounted in `app.js` behind `authenticateToken, authorizeAdmin()`. New `src/routes/adminRoutes.js`. **Does NOT re-create controllers**: it binds to existing controller functions and adds only missing functions to their **home controllers**:
   - Cross-domain aggregates (dashboard) → new thin `src/controllers/adminController.js` (glue only, uses existing prisma/service patterns).
   - Enrollments list → `enrollmentController.js`. Global attempts/quizzes index → `quizController.js`. Submissions → `assignmentController.js`. User filters → `userController.js`.
3. **FE: reuse house patterns.** Pages are `'use client'` components using `services/admin*.ts` wrappers over `lib/api-client.ts` + local state (NOT new Redux slices, NOT React Query). Charts = `recharts` + shadcn `ui/chart.tsx` (already installed, currently unused), lazy-loaded. Tables = **`@tanstack/react-table`** (new dep, user-approved) wrapped in a generic `DataTable<T>` over the unused `ui/table` + `ui/pagination` + `ui/skeleton`.
4. **Design system (user directive + ui-pro-max skill):** the admin console is a **dark, dense dashboard** generated by the `ui-ux-pro-max` skill (design system persisted at `L:\E-LRN-FRONTEND\a-e-lrn-frontend\design-system\e-learning-admin-console\MASTER.md`): dark tech palette (bg `#0F172A`, card `#1B2336`, accent/status `#22C55E`), Fira Code + Fira Sans fonts, glassmorphism-lite borders, subtle motion, status colors (green/amber/red), a11y minimums (4.5:1 contrast, visible focus, reduced-motion). **Scoping rule:** all tokens live as CSS variables scoped under a `.admin-console` wrapper in `globals.css` — shadcn primitives resolve contextually inside admin pages while the **student app stays light/untouched**. Legacy admin quiz pages get restyled onto this system (Task 0.3).
5. **Conventions locked in AGENTS.md must hold:** `{ success: true, data }` envelope, `?page=&limit=` + `meta: { total, page, limit, totalPages }`, structured error codes, cookie auth, Arabic labels. Do NOT touch: Bunny webhook order, cookie/auth model, sequential-gate logic, payment-disabled behavior.
6. **Integration seams for future features:**
   - Sidebar = one array `{ group, items[{ label, href, icon }] }` in `AdminSidebar.tsx`.
   - Admin API = one route file; new endpoints only in their home controller.
   - New pages = new `app/admin/<slug>/page.tsx` behind the existing layout guard.
   - `GET /admin/dashboard` = single object; a new KPI = one key.
7. **Backend packages:** none new. **Frontend packages:** add `@tanstack/react-table` only.

## Risks and Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| `DELETE /user/:id` cascades across many relations / FK errors | Med | Verify in Task 1.1; document behavior; prefer graceful error over raw 500 |
| Global rate limit 100 req/15min (admin pages do many calls) | Low | One dashboard call per page; lazy-load sections; consider a higher per-IP limiter for `/admin` if needed (logged, flagged) |
| `answerKey`/`correctOption` leak in new list endpoints | High | Explicit field-pruning in serializers; verify in AC + a dedicated API check |
| Admin pages hit uncommitted FE WIP files | Low | Only create new `app/admin/**`, `components/admin/**`, `services/admin*.ts` |
| TanStack table added without need → complexity | Low | Single `DataTable<T>` wrapper; columns-only per section |
| Charts heavy on admin shell | Low | `next/dynamic` lazy import in Task 4.1 |
